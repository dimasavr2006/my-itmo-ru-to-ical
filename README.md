# ITMO schedule to iCalendar converter

Сервис, который ходит на my.itmo.ru за расписанием и экспортирует его как iCalendar с публичной ссылкой. Позволяет автоматически и с автообновлением экспортировать пары в календари Google, iCloud и другие.

## Автообновление без сервера: GitHub Actions + GitHub Pages

GitHub Actions получает личное расписание за текущий учебный год и публикует
`.ics` через GitHub Pages. Постоянно работающий сервер и Docker не нужны.
Расписание обновляется каждые 6 часов: ориентировочно в **03:23, 09:23, 15:23
и 21:23 по Москве**. Запуск также доступен вручную. GitHub может задерживать
запуски; получение изменений телефоном зависит от календарного приложения.

### 1. Создайте форк и включите Actions

Сделайте [форк оригинального репозитория](https://github.com/iburakov/my-itmo-ru-to-ical/fork)
в свой аккаунт. Для бесплатного GitHub Pages нужен публичный репозиторий.
В форке откройте **Actions** и разрешите запуск workflows, если GitHub предложит.
Автоматическая сборка Docker-образа в форках отключена.

### 2. Добавьте три секрета

В своём форке откройте **Settings → Secrets and variables → Actions →
New repository secret** и добавьте:

| Имя секрета | Значение |
| --- | --- |
| `ITMO_ICAL_ISU_USERNAME` | Логин ИСУ ИТМО |
| `ITMO_ICAL_ISU_PASSWORD` | Пароль ИСУ ИТМО |
| `ITMO_ICAL_CALENDAR_TOKEN` | Случайная строка для постоянного адреса календаря |

Для токена разрешены 32–128 символов `A–Z`, `a–z`, `0–9`, `_` и `-`.
Сгенерировать подходящий токен локально можно так:

```powershell
uv run --no-python-downloads --python 3.13 python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Сохраните токен у себя: GitHub не показывает значение секрета после сохранения,
а он потребуется для составления ссылки. Смена пароля ИСУ требует обновить
только `ITMO_ICAL_ISU_PASSWORD`; адрес календаря при этом сохранится.
Смена `ITMO_ICAL_CALENDAR_TOKEN` изменит адрес, после чего понадобится новая подписка.
Не добавляйте пароли, токены и личные `.ics` в исходники или коммиты.

### 3. Включите GitHub Pages

Откройте **Settings → Pages → Build and deployment → Source** и выберите
**GitHub Actions**. Если настроены ограничения окружения `github-pages`,
разрешите публикацию из основной ветки `main`.

### 4. Запустите первую выгрузку

Откройте **Actions → Update calendar and deploy to Pages → Run workflow**,
выберите `main` и запустите workflow. После успешных `build` и `deploy`
станут доступны:

```text
Страница подписки:
https://<ваш-github-логин>.github.io/<имя-репозитория>/<ваш-токен>/

Постоянная ссылка на календарь:
https://<ваш-github-логин>.github.io/<имя-репозитория>/<ваш-токен>/schedule.ics
```

Для форка `dimasavr2006/my-itmo-ru-to-ical` начало ссылки:
`https://dimasavr2006.github.io/my-itmo-ru-to-ical/`.
Ссылка на корень сайта из результата deployment не содержит токен и не показывает расписание.

### 5. Подпишитесь на календарь

- **Google Календарь:** в веб-версии откройте «Другие календари → + → Добавить
  по URL» и вставьте полную HTTPS-ссылку на `schedule.ics`.
- **Apple Calendar / iPhone:** откройте страницу подписки и нажмите
  «Подписаться», либо добавьте календарь по подписке вручную, используя полную ссылку.
- **Outlook:** выберите добавление календаря из интернета / подписку по URL.

Для автообновления нужна **подписка по ссылке**. Скачивание и импорт `.ics`
создают разовую копию. Для существующих занятий сохраняются UID, поэтому
изменение аудитории обновит занятие при следующей синхронизации.

### Доступ к опубликованному расписанию

**Считайте календарь публичным.** GitHub Pages не проверяет пароль при скачивании.
Случайный путь и `robots.txt` уменьшают случайное обнаружение, но не обеспечивают
приватность: в публичном форке артефакты Actions также доступны другим
пользователям GitHub. Они хранятся один день. Не используйте этот вариант,
если расписание должно быть доступно исключительно вам.

В Pages-версию попадают название пары, дата, время, корпус и аудитория.
Группа, преподаватель, Zoom-ссылки и пароли, примечания и другие дополнительные
поля исключены. Логин и пароль ИСУ читаются только из Secrets на этапе выгрузки;
в сайт и Git-историю они не записываются. Корневая страница не раскрывает путь
к календарю. В логах workflow не печатаются токен, полный адрес и ответы авторизации.

### Ошибки и обслуживание

- Если авторизация, API или сеть недоступны, выгрузка завершается с ошибкой,
  а прежняя публикация остаётся доступна. Пустое расписание также блокирует
  публикацию, чтобы временный пустой ответ не удалил все занятия у подписчиков.
  Если у вас действительно нет занятий, workflow будет завершаться с ошибкой
  до появления непустого расписания.
- Границы учебного года — 1 августа и 31 июля — выбираются по московской дате.
- Запуски по расписанию используют код основной ветки. После изменения секретов
  нажмите **Run workflow**, чтобы не ждать следующего запуска.
- GitHub отключает scheduled workflows публичного репозитория после **60 дней
  без активности**. Если обновления остановились, откройте Actions, выберите
  workflow и нажмите **Enable workflow**, затем **Run workflow**.
  [Правила GitHub о scheduled workflows](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/disable-and-enable-workflows).
- Секреты доступны коду workflow: перед переносом чужих изменений в свой форк
  проверяйте изменения в `.github/workflows` и `src`. Выгрузка не запускается
  на pull request и в дополнительных ветках.

Для локальной проверки без доступа к ИСУ:

```powershell
uv venv --python 3.13 --no-python-downloads
uv pip install -r requirements-calendar.txt
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

## Разовая выгрузка .ics без Docker (через uv)

Для получения файла не нужно запускать сервер или настраивать синхронизацию.
Из папки проекта выполните в терминале:

```powershell
uv run --no-cache --no-python-downloads src/export_ics.py
```

`uv` выберет уже установленный Python 3.11–3.13 и установит зависимости скрипта
во временное окружение. Флаг `--no-python-downloads` запрещает загрузку
дополнительного интерпретатора, а `--no-cache` использует временный каталог
для зависимостей вместо постоянного кеша. Введите логин
и пароль ИСУ в терминале. Ввод пароля скрыт; скрипт не сохраняет его в файл.
После успешной выгрузки рядом с README появится `schedule.ics` с личным
расписанием за текущий учебный год (с 1 августа по 31 июля).
Этот файл можно разово импортировать в календарь.

Другое имя файла можно указать так:

```powershell
uv run --no-cache --no-python-downloads src/export_ics.py --output my-schedule.ics
```

После сохранения файла программа завершится. Чтобы выгрузить расписание заново,
повторите команду. Повторный запуск перезаписывает выбранный файл.
Если авторизация или API ИТМО изменились, может потребоваться обновление кода;
проверить вход без вашей учётной записи нельзя.

## Что нужно для сервиса с синхронизацией

Логин и пароль от ИСУ, поэтому безопасности ради захостить себе сервис придётся самостоятельно.

Нужен **личный** сервер (без доступа у посторонних) с `docker` на нём.

## Как завести

1. Подставить username/password в команду и запустить контейнер:

   ```bash
   APP_PORT=35601

   docker run -d \
      --restart=unless-stopped \
      --name itmo_ical \
      -p=$APP_PORT:35601 \
      -e ITMO_ICAL_ISU_USERNAME=100000 \
      -e ITMO_ICAL_ISU_PASSWORD=XXXXXXXXXXXXX \
      ghcr.io/iburakov/my-itmo-ru-to-ical
   ```

2. Получить публичную ссылку на .ics:

   ```bash
   URL_PATH=$(docker logs itmo_ical 2>&1 | grep -oh '/calendar/.*')
   HOST_IP=$(curl -s ipinfo.io/ip)

   echo "http://$HOST_IP:$APP_PORT$URL_PATH"

   # должно выглядеть как-то так:
   # http://93.184.216.34:35601/calendar/gnKZT88jeuKDdhh7Ow8mwsAbMpIyVKaCBpl2CtqJqYI
   ```

3. Если по ссылке скачивается .ics файл, всё работает
4. Импортировать ссылку в свой календарь. Он будет периодически повторять запрос для получения обновлений - изменяющиеся аудитории теперь не беда ;)

PS. Ссылка содержит хеш имени пользователя и пароля, чтобы она была и неподбираемой для посторонних, и относительно постоянной без использования какого-либо хранилища. Стоит иметь в виду, что меняется username/password - меняется ссылка.

## Дополнительно

⚠ Пароль от ИСУ можно извлечь из контейнера с помощью `docker inspect` / `docker exec`. Безопасность своих ключей - ваша зона ответственности. Убедитесь, что:

- к серверу нет доступа у других людей,
- включен фаервол,
- отключена SSH авторизация по паролю и root login,
- и.т.п.

Docker образы собираются и пушатся в реестр с помощью GitHub Actions - исходники в этом репозитории, соответствующие скрипты сборки и логи общедоступны. Если всё равно стрёмно доверять пароль рандомному образу, можно склонировать репозиторий и сделать `docker build` из исходников самостоятельно.

Также из коробки поддерживается мониторинг ошибок с помощью [Sentry](https://sentry.io/). Можно создать проект (Python/Flask) и передать [DSN](https://docs.sentry.io/product/sentry-basics/dsn-explainer/) в переменную окружения `ITMO_ICAL_SENTRY_DSN` при старте контейнера.
